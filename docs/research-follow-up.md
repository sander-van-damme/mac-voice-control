## Current official contracts

Read [models](https://docs.typesafe.ai/models.md), [images](https://docs.typesafe.ai/images.md), [Box](https://docs.typesafe.ai/primitives/box.md), [HTTP API](https://docs.typesafe.ai/api/system-one.md), [Score](https://docs.typesafe.ai/primitives/score.md), and [confidence](https://docs.typesafe.ai/confidence.md) directly. Jev 1.14.0 remains current; both aliases resolve to it. The generic model table still says text, while the dedicated image documentation explicitly enables images for 1.13/1.14 and Box for 1.14. Preserve the version and experimental opt-in header. The existing referenced JPEG asset format is correct. Limits remain 280–1568 pixels per side, 16 MiB/image, 32 MiB body/expanded input, default 64k request/32k question context. Price is $0.042/M input tokens; outputs free. Rate limits are organization-specific. Confidence is not calibrated probability of task success. A Box always returns a box, including absent targets: retain the independent presence gate.

Read Apple’s [AXUIElement](https://developer.apple.com/documentation/applicationservices/axuielement), [SCScreenshotManager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager), and [SpeechTranscriber](https://developer.apple.com/documentation/speech/speechtranscriber) documentation, and [Chromium accessibility design](https://www.chromium.org/developers/design-documents/accessibility/). Native AX remains synchronous IPC, not a complete visual scene. Full Chrome AX is enabled on demand; dynamic/canvas controls and virtualized content still need screenshots. Preserve negative display coordinates, pixel/point separation, password-region masking, display capture with our UI excluded, and fresh focus checks. macOS 26 SpeechTranscriber does not establish mixed Dutch–English accuracy on macOS 14.2, so changing speech providers has no evidential basis yet. Keep local Ultra; use the real-Mac corpus before choosing an Apple fallback or WhisperKit.

Read [Codex App Server](https://developers.openai.com/codex/app-server) again: supported account APIs and a client-owned JSON-RPC process are the integration boundary. Do not extract authentication files or assume the desktop app exposes a reusable process endpoint. Keep optional escalation deferred and independent of normal navigation.

## Architecture decision before changes

Adopt PR #1 as the implementation foundation: it already has a native product, injectable core, local speech downloads, real image requests, closed actions, tests, signing scripts, and a successful [macOS final-head build](https://github.com/sander-van-damme/mac-voice-control/actions/runs/40401811536). That historical artifact does not validate our new changes. Preserve upstream notices and the existing packaging route.

Strengthen the existing architecture rather than add another framework:

1. Bind every decoded action to the exact observation that produced its candidates. A response for `e0` on one screen must never be interpreted against `e0` on another.
2. Give confirmations an opaque identity and monotonic deadline, checked directly when resolved and before execution. A delayed UI callback must not approve a replacement prompt. Timers provide UI cleanup, not authority.
3. Check the whole-goal time budget after suspension points as well as before an iteration. Cancellation while awaiting confirmation must resume the continuation.
4. Keep the original goal and latest correction separately; expire wake-free correction authority and clear it on Stop. Prevent ordinary conversation beginning “actually” from reviving an old task after an unlimited interval.
5. Reject cropped/incomplete audio and stale queued commands. Add repeatable Dutch, English, mixed-language and dictation fixtures; these test routing only, not acoustic accuracy.
6. Exercise GUI session cancellation and model-download recovery through a fake speech provider; retain synthetic native pixel tests. Publish fresh macOS build/test/DMG evidence, not inferred success.
7. An additional source review found that `AccessibilityReader.collect` required an AX window before capture. That contradicts treating AX as supplementary. Use Apple's [CGWindowListCopyWindowInfo](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo(_:_:)) metadata for a guarded screenshot-only fallback: retain the top visible window's PID/ID/frame, revalidate all three, and refuse typed input without an AX field. A visual click must also pass a live topmost-window check; missing AX is not permission to click another process. No window titles or field values are required by this fallback.

Automatic zoom refinement, Vision OCR, learned VAD, and Codex remain separate improvements. They cannot replace the still-required live TypeSafe, microphone, Chrome, multi-monitor, and signing acceptance checks. No latency, WER, or successful desktop-control numbers have been measured in this Linux environment.

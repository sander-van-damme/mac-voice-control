# Research and implementation decision record

A fresh independent source/API review and the rationale for extending PR #1 are recorded in [research-follow-up.md](research-follow-up.md).

Research date: 26 October 2026. This document was written before application implementation. Source review is evidence about design, not a claim that we reproduced upstream benchmarks. The development host is Linux; desktop behavior, ASR accuracy, and live Jev decisions require separate validation.

## Recommendation

Build a small SwiftUI application, a portable Swift decision core, ScreenCaptureKit observation, bounded Accessibility extraction, and a closed action registry. Pin Jev 1.14.0 and FluidAudio by commit. Use local Parakeet Ultra for both Dutch and English, with a mandatory leading wake phrase for commands. Keep speech capture active during execution so cancellation remains available. No up-front generative planner and no browser extension.

Reuse FluidAudio's ASR and model downloader as a dependency, and adapt two small MIT-licensed components from jev-use: Keychain storage and wake-phrase parsing. Do not adopt its entire desktop implementation: its large files and text-only action contract would require extensive replacement to make screenshots first-class. The architecture and safety findings below inform newly written perception, execution, and loop code. See THIRD_PARTY_NOTICES.md for exact attribution.

## TypeSafe: verified wire contract

Official sources: [models](https://docs.typesafe.ai/models), [HTTP API](https://docs.typesafe.ai/api/system-one), [images](https://docs.typesafe.ai/images), [Box](https://docs.typesafe.ai/primitives/box), [Choice](https://docs.typesafe.ai/primitives/choice), [Noul](https://docs.typesafe.ai/primitives/noul), [Score](https://docs.typesafe.ai/primitives/score), [confidence](https://docs.typesafe.ai/confidence), [errors](https://docs.typesafe.ai/api/errors), [fan-out](https://docs.typesafe.ai/patterns/fan-out).

The official models page currently lists 1.14.0 as newest and both jev-latest and jev-preview as aliases to it. Older third-party pages still claim latest is 1.13: do not use those for version selection. The models table still describes text input; the dedicated images/Box pages explicitly document experimental image support in 1.13 and 1.14, and Box in 1.14. We pin `jev-1.14.0`, refuse incompatible responses, and never substitute a text-only model.

POST `https://api.typesafe.ai/v1/systemone`, Bearer authorization, JSON body with `model`, `state`, `questions`, and `assets`. Include `TypeSafe-Danger-Zone-Images: true`. Images use a unique string reference in state and a top-level asset `{type: image, format: jpg, data_base64: ...}`. This is not an OpenAI messages/image_url API. Reference the asset once in state; question instructions refer to that state field. Repeating asset references increases expanded input. Multipart is more efficient; bounded JPEG/base64 is simpler for our single small image and stays well below the body limit.

Current image limits: still PNG/JPEG, each side 280–1568 pixels, at most 16 MiB per image, 32 MiB request/expanded input limits. Oversize images are rejected, not automatically resized. Resize to a maximum 1280-pixel side with padding for narrow windows. Preserve the content rectangle separately from the padded image so boxes cannot click padding. Keep crop, image, and desktop coordinate transforms explicit. Images are billed as input tokens; the docs do not supply a reliable image-token estimator. Use returned usage, not guessed pixel pricing.

Questions run independently against shared state; one question cannot depend on another answer in that request. Ask speculative operation, target, text span, completion, target presence, sensitivity, and Box questions together. Use only heads needed by the selected operation. Choice returns a label, probabilities, and confidence; Noul returns a 0–1 truth probability; Score returns an expected value over ordered levels; Box returns normalized top/left/bottom/right plus confidence. Box has no absent result: a plausible box alone never authorizes a click. Independent presence, geometry, confidence, live focus, and freshness checks are required.

Choice confidence describes concentration of the probability distribution, not a guarantee of correctness. Require both selected probability and confidence, validate all distributions and labels, and reject malformed responses. Box confidence thresholds are application policy and uncalibrated until our own target corpus is measured. Initial conservative thresholds are documented in architecture.md.

Input is $0.042 per million tokens and output is free on the current direct pricing page. Default context limits are 64k per request and 32k per question. Organization-specific token/request rate limits are shown in the console; no universal RPS is assumed. Use cancellation-aware URLSession with a timeout, bounded transient retries honoring Retry-After, and fresh observation after delayed responses. Never retry an executed action on an ambiguous result. HTTP 400/401/403 are surfaced; no automatic model fallback. Record latency and usage without response bodies, screen text, keys, or screenshots. Published marketing latency is not this application's measured latency.

## macOS observation and control

Primary references: [AXUIElement](https://developer.apple.com/documentation/applicationservices/axuielement), [messaging timeout](https://developer.apple.com/documentation/applicationservices/axuielementsetmessagingtimeout(_:_:)), [hit testing](https://developer.apple.com/documentation/applicationservices/axuielementcopyelementatposition(_:_:_:_:)), [AXObserver](https://developer.apple.com/documentation/applicationservices/axobserver), [ScreenCaptureKit sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos), [SCScreenshotManager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager), [Vision OCR](https://developer.apple.com/documentation/vision/recognizing-text-in-images).

AX supports application/window trees, focused element, roles/subroles, labels, values, positions, sizes, enabled state, actions, notifications, and point hit-testing. It requires Accessibility trust. Calls are synchronous IPC and may fail, block, or return stale proxies. Bound per-call timeout, visited nodes, depth, elapsed walk time, emitted controls, and string lengths. Walk on a background serial queue; never block the Stop button. Secure elements must be detected before reading labels/descriptions/values. Do not read secure values at all. Avoid serializing ordinary field values by default, since even non-secure fields can contain private data.

[Chromium's design documentation](https://www.chromium.org/developers/design-documents/accessibility/) says it enables the full tree on demand through AXEnhancedUserInterface. Actual jev-use source also sets AXManualAccessibility for Electron. These attributes are implementation details rather than a stable Apple API. Set them sparingly per process, re-poke only after a sustained empty web tree, and report incomplete observation. AXWebArea is useful evidence that web content is available, never proof of completeness.

Chrome exposes semantic HTML controls, links, forms, tabs, and menus when the renderer's accessibility tree is active. ARIA quality and app behavior determine coverage. GitHub/Gmail ordinary links and forms tend to have meaningful semantics; canvas-based Miro content, custom controls, virtualized lists, and rich editors can be absent or incomplete. Google Docs may require its own accessibility mode. These are expected behaviors to test, not claims that we ran those applications here. Upstream issue #22 below demonstrates that even tab counts can be incomplete. Never equate missing AX nodes with missing visual objects.

Capture the display containing the frontmost window, crop to that window's visible intersection, and exclude our own app with a ScreenCaptureKit filter. Display capture preserves occlusion, unlike isolated-window capture which can show content behind another window. Support negative display origins and Retina by using Core Graphics global point coordinates separately from image pixels. Recheck process, focused window geometry, focused field, and screenshot before executing. A window moving while Jev is deciding invalidates its decision.

Screenshots accompany every decision in the baseline. Selective screenshots might be cheaper, but no source demonstrates equivalent reliability for this application's visual tasks. Fresh screenshots provide a measurable baseline; only reduce their frequency after controlled experiments. Dense-screen small targets may require a crop/refinement pass. The first implementation uses the current window crop; automatic second-stage zoom is an extension, not silently assumed to exist.

Vision OCR can add labels for canvas text and support matching a visual box to AX geometry. It adds work and duplicate context; begin with screenshot plus AX and retain OCR as an explicit later improvement. A visual point can first be matched to a known AX control and hit-tested; prefer AXPress when identity and geometry match, otherwise use guarded mouse events. AXObserver notifications could reduce polling but are unreliable in some web apps; per-step fresh capture remains authoritative.

## Speech comparison

References: [SFSpeechRecognizer on-device support](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition), [Apple SpeechAnalyzer session](https://developer.apple.com/videos/play/wwdc2025/277/), [SpeechTranscriber](https://developer.apple.com/documentation/speech/speechtranscriber), [AssetInventory](https://developer.apple.com/documentation/speech/assetinventory), [FluidAudio Ultra](https://github.com/FluidInference/FluidAudio/blob/1b0ed50d686873128a4129b3510ce3914c849bab/Documentation/ASR/ParakeetUltra.md), [FluidAudio models](https://github.com/FluidInference/FluidAudio/blob/1b0ed50d686873128a4129b3510ce3914c849bab/Documentation/Models.md), [WhisperKit](https://github.com/argmaxinc/WhisperKit).

| Provider | Useful properties | Trade-offs and conclusion |
|---|---|---|
| SFSpeechRecognizer | Native, partial/final results, no bundled weights; on-device capability can be checked | Locale-specific; set requiresOnDeviceRecognition to avoid network fallback. Availability depends on assets/device/locale. No evidence here of robust automatic Dutch–English code switching. Session renewal and silence errors need care. Optional future fallback, not default. |
| SpeechAnalyzer / SpeechTranscriber | Newer on-device streaming API, volatile/final results, AssetInventory downloads; Apple manages assets | macOS 26/hardware/locale availability must be checked at runtime. A chosen locale is part of configuration; do not promise mixed-language behavior. Raising minimum OS alone does not prove accuracy. |
| FluidAudio Parakeet Ultra | Native Swift/Core ML/ANE, multilingual model including Dutch and English, downloadable assets, replaceable provider | About 595 MB encoder plus decoder/preprocessor/vocabulary; first load compilation and memory are material. Multilingual does not prove within-sentence switching accuracy. Best supported starting point on Apple Silicon; benchmark with the user's accents. |
| Parakeet v3 | Same multilingual family, smaller ~445 MB encoder, library default | Ultra is upstream's recommendation based on broader multilingual evaluation. Pin explicit .ultra rather than accidentally taking the default. |
| Parakeet EOU | Real streaming end-of-utterance model | English-only variant is unsuitable as the main Dutch recognizer. |
| WhisperKit | Local multilingual Whisper, multiple size/speed choices, streaming support | Viable alternative, but decoding and larger models can cost latency/memory. Retain provider boundary; do not add a second large runtime without measured need. |

FluidAudio reports multilingual FLEURS and English results; these are upstream measurements, not this app's WER or latency. No reviewed benchmark directly establishes Dutch–English code-switching quality for our commands. The manual corpus includes Dutch, English, and mixed utterances and must record intended/transcribed text and command success separately.

Use bounded microphone utterances with silence segmentation and local ASR. Final utterances alone may start actions. A local partial stop monitor may cancel, but partial transcripts never authorize ordinary actions. Wake phrase must lead each command; ordinary conversation is ignored. Explicit dictation is a separate routing mode and cannot turn its content into commands. Corrections cancel the old run and start a fresh observation with a short previous-goal/action context. The microphone remains active during actions; finite queues prevent accumulated stale commands.

## Optional Codex escalation

The local environment has a Codex executable; its presence here does not establish what is installed or authenticated on the user's Mac. [Official App Server documentation](https://developers.openai.com/codex/app-server) describes JSON-RPC initialization, account/authentication operations, thread/turn lifecycle, local image inputs, structured outputs, and approval events. A client-owned `codex app-server` process can use supported account flows; do not read/copy authentication files. An already running GUI process is not a guaranteed public reusable endpoint. Query account state through the protocol and use supported login when needed. Process startup, handshake, and inference latency need measurement. Defer this optional integration: core control works with only TypeSafe, and substantial prose drafting is honestly unsupported rather than secretly delegated.

## Distribution and verification

Use Apple Silicon macOS 15 hosted runners with an explicit Xcode 26.3 selection (Swift 6.2 supports FluidAudio's traits, so unused TTS/diarization/binary normalization can be excluded). Verify against the [runner image manifest](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-arm64-Readme.md). Pin action commits, cache package checkouts keyed by Package.resolved, and build/test the same SwiftPM product packaged into the app. Avoid ASR model downloads in routine tests.

Create a .app bundle with microphone/speech descriptions and hardened-runtime entitlements; ad-hoc sign development builds, or use Developer ID plus Apple's notarytool and stapler when credentials are configured. Package with hdiutil into DMG and upload Actions artifacts; version tags can create Releases. Signing credentials enter an ephemeral CI keychain, are cleaned even on failure, and never enter the app. [Apple notarization guidance](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) is authoritative. Unsigned/ad-hoc development artifacts are explicitly distinct from notarized releases.

No real Mac screen, microphone corpus, TypeSafe key, or Apple distribution certificate is attached to this Linux environment. Build results, test counts, and artifact URLs are recorded separately after implementation. No end-to-end or performance claim follows from compilation alone.
